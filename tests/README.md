Один файл `tests/run_tests.py`, никаких фреймворков и браузера: только
стандартная библиотека Python. Тест сам обходит проект, сам находит страницы,
модули, стили и словари — и на каждый провал показывает файл, строку и причину.

---

## ⚡ Быстрый старт

```bash
python tests/run_tests.py             # всё (~6 с), язык — как в настройках приложения
python tests/run_tests.py --fast      # без HTTP-прогона и node --check
python tests/run_tests.py --only js,live
python tests/run_tests.py --list      # список групп
python tests/run_tests.py --strict    # пропуски = провал (для CI)
python tests/run_tests.py --lang en   # вывод по-английски
```

| Флаг | Что делает |
|---|---|
| `--fast` | пропускает живой сервер и `node --check` |
| `--only js,live` | только выбранные группы, через запятую |
| `--list` | печатает ключи групп |
| `--strict` | пропущенная проверка считается провалом |
| `-v`, `--verbose` | время каждой группы и все проблемы без сворачивания |
| `--lang ru\|en`, `-l` | язык вывода; без флага — выбранный в приложении |
| `--pause` / `--no-pause` | ждать Enter в конце или нет |

Зависимостей нет — только стандартная библиотека Python. `node` нужен для
проверки JS и словарей; без него эти проверки помечаются пропущенными
(с `--strict` это провал).

Код возврата: `0` — чисто, `1` — есть провалы, `2` — неизвестная группа.
В терминале в конце ждёт Enter, в пайпе и CI — нет.

## 🧭 Как это работает

Не список файлов, а сам проект: страницы (`*.html`), Python, JS, CSS и JSON
ищутся обходом с любой глубиной. Добавили новую папку, страницу, модуль или
словарь — они попадают в проверки без правки теста. Не трогаются только чужие
каталоги: `node_modules`, `vendor`, `__pycache__`, `venv`, `dist`, `build`.

Точки входа для «мёртвого кода» тоже определяются сами: файл с
`if __name__ == '__main__'` или упомянутый в лаунчере (`.bat`, `.sh`, `.ps1`)
считается запускаемым, а не импортируемым.

## 🔤 Язык вывода

Баннер, заголовки групп, названия проверок, причины провалов и итог есть на
двух языках, и тест говорит на том, который пользователь выбрал в интерфейсе:

```bash
python tests/run_tests.py             # язык из настроек приложения
python tests/run_tests.py --lang en   # English output
python tests/run_tests.py --lang ru   # русский
```

Выбор пользователя хранит сервер в `R34/.secrets/language.json` — файл вида
`{"lang": "en"}`. `saved_language()` читает его (и передаёт тот же язык
серверу в `ЖИВОМ СЕРВЕРЕ`, чтобы прогон не менял настройку), а `preset_lang()`
берёт этот язык по умолчанию. Флага `--lang` достаточно, чтобы говорить на
другом языке, не трогая настройки; если файла нет или в нём что-то чужое —
`en`, как и у сервера по умолчанию.

Перевод живёт в таблице `TRANSLATIONS` в начале `tests/run_tests.py`: ключ —
готовая русская фраза. Новая фраза без перевода остаётся по-русски — это видно
сразу, и её достаточно дописать одной строкой. Хвост после ` · ` (строка
исходника) не переводится никогда, иначе поехал бы код.

## ❗ Как читать провал

Каждая проверка возвращает список проблем вида `файл:строка — причина`.
Пустой список — прошло. Провал всегда говорит, где и почему:

```
  СТАТИКА                                               × 3/4
    × скобки в 9 CSS
        R34/static/css/devpanel.css:310 — не закрыт блок «{»

  JS: МОДУЛИ                                            × 1/2
    × 125 импортов разрешаются
        R34/static/js/main.js:25 — import ./components/devPanel-missing.js: файла нет
```

В конце провалы повторяются блоком «Что не так». Для HTTP-проверок причина
дополняется статусом, телом ответа и строкой из лога сервера.

В проверках мёртвого кода причина показывает саму строку исходника — по
одному имени в консоли непонятно, о чём речь:

```
    × 176 функций и классов используются
        handlers/console_ui.py:430 — step нигде не используется · def step(self, text, glyph='•••'):
    × 110 экспортов JS используются
        R34/static/js/a.js:12 — export RippleEffect нигде не используется · export class RippleEffect {
```

Если мёртв не кусок кода, а файл целиком, строки нет — вместо неё явная
пометка, чтобы не путать с находкой внутри файла:

```
    × 10 CSS подключены
        R34/static/css/orphan.css — файл целиком: нет <link> ни на одной странице
        handlers/legacy.py — файл целиком: модуль никто не импортирует
```

В консоли первые 6 проблем на проверку, остальные сворачиваются в «… и ещё N»;
с `-v` выводятся все.

## 🗂 Группы

| Заголовок | Ключ | Что проверяет |
|---|---|---|
| `PYTHON` | `python` | компиляция всех `.py`, импорт `server`, маршруты, защищённые `/api`, обращения к `/api` из JS/HTML |
| `СТАТИКА` | `assets` | ссылки на статику со всех страниц, дубли `id` на странице, парность тегов HTML, скобки в CSS, неопределённые `var(--x)`, `url()`/`@import` |
| `JS: МОДУЛИ` | `js` | относительные импорты, `node --check` |
| `ПЕРЕВОДЫ` | `i18n` | пары ru→en, словарь `EN`, переводы без текста в интерфейсе, строки консоли в двух языках |
| `КОНСОЛЬ` | `console` | формат времени, фильтр лога, стартовый отчёт |
| `СЛУЖЕБНАЯ ПАНЕЛЬ` | `panel` | подключение, видимость в мини-играх, перетаскивание с запоминанием места, мобильные стили, подписи; если панели в сборке нет вообще — группа пропускается, а не падает |
| `МЁРТВЫЙ КОД` | `dead` | модули без импортов/`<script>`, функции и классы без вызовов, неиспользуемые `export`, CSS без `<link>`, мёртвые переменные CSS |
| `ЛАУНЧЕРЫ` | `launchers` | `.bat` в UTF-8/CRLF с `chcp 65001`, termux-скрипт |
| `ЛОКАЛЬНЫЕ ДАННЫЕ` | `data` | все JSON проекта (`game_data`, `.secrets`, новые конфиги) |
| `ЖИВОЙ СЕРВЕР` | `live` | статусы и Content-Type реального сервера, недоступность `.secrets`, `nosniff` на статике, `no-store` на `/api` |

## 🕳 Что считается «мёртвым»

Проверки намеренно осторожны, чтобы не ругаться на живой код:

- Python-функция считается используемой, если её имя встречается хоть где-то
  ещё: вызов, атрибут или импорт (в том числе под алиасом). Строковые
  литералы намеренно не считаются: строка `'step'` в теле функции не делает
  её живой.
- Обработчики Flask пропускаются: они вызываются через декоратор
  (`@app.route`, `@bp.before_request` и т. п.), а не по имени.
- Точки входа и `tests/` не обязаны кем-то импортироваться.
- JS-экспорт считается живым, если имя встречается где-то ещё: в другом
  модуле, на странице или в своём же файле. Так проверка не ругается на
  нормальные внутренние экспорты; мёртвыми остаются только те, что не
  упоминаются ни разу.
- `login.js` живёт в `login.html`: страницей считается любая `*.html`.
- Переменная CSS считается живой, если её читают через `var(--x)` или она
  упомянута в JS/HTML (`style.setProperty('--x', …)`). Чтение без определения
  и без `var(--x, запасное)` — отдельная проверка в `СТАТИКЕ`: такое свойство
  браузер молча выбрасывает.

## 👀 Слепые зоны

Чего проверка не увидит: методы классов и вложенные функции, вызов по
вычисляемой строке (`getattr(mod, f'{kind}_handler')`), модули из
`importlib.import_module`, адреса API, собранные из переменных
(`fetch(base + '/x')`), переводы с подстановками (`${…}`) и теги, которые
JS добавляет в рантайме. На этих случаях она скажет «мёртвое» или промолчит —
правьте allowlist, а не код.

## ➕ Новая проверка

```python
def check_mine(r):
    problems = []
    for lineno, line in numbered(SOME_FILE):
        if line != 'ok':
            problems.append(f'{where(SOME_FILE, lineno)} — что не так')
    r.check('короткая подпись', problems)
```

Затем `('mine', 'ЗАГОЛОВОК', check_mine)` в `GROUPS`. Если название проверки или
причина провала должны быть и по-английски — добавьте фразу в `TRANSLATIONS`.
Проверка не должна менять данные пользователя.

## ⚠️ Осторожно: GET /

**Не запрашивайте `GET /`.** Маршрут проверяет ключ на rule34 и при неудаче
удаляет `R34/.secrets/api_credentials.json` — прогон стёр бы вход. Для «страница
отдаётся» используется `/login`. В HTTP-прогоне прокси отключён
(`ProxyHandler({})`), иначе на Windows loopback уходит в системный прокси и
висит, и запрещены редиректы (`NoRedirect`), чтобы `/login` не утянул на `/`.
